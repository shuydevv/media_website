## 1. Что строим

Новый Telegram-бот (своё название, отдельный от @poltavskiy_ege_bot) ✅. Путь:

```
реклама → /start в боте диагностики → кнопка «Пройти диагностику»
  → Mini App (страница на p-ege.ru внутри Telegram) → тест 5 блоков
  → результат: балл сейчас, потенциал, пробелы
  → «Хочешь улучшить свои знания?» → «Александр» пишет мягкий вопрос
  → живой диалог админа → админ договаривается о бесплатном групповом
    занятии и в назначенный день вручную шлёт ссылку-приглашение
```

Цель воронки — **живой диалог с админом**, не запись кнопкой ✅. Бот сам
занятие не предлагает и не записывает; его задача — довести до момента, когда
человек ответил «Александру».

Контакт (Telegram) есть **до** теста, поэтому результат не прячем: всё
показываем сразу на странице, бот дублирует краткую сводку в чат.

Предмет — только обществознание ✅. Движок пишем без жёсткой привязки к
предмету (блоки и банк — из конфига/JSON), но историю сейчас не делаем.

Ключевая эмоция на выходе: «кое-что я знаю, вот конкретные дыры, и их можно
закрыть». Не «я ничего не знаю».

## 3. Мультибот (этап 0) ✅

Сейчас весь Telegram-код рассчитан на одного бота. Места, где это зашито:

- `TelegramApi::funnel()` — один токен из `services.telegram_funnel.bot_token`;
  вызывается в `FunnelBot::make()`, `SendSiteLead`, `SendInboundLead`,
  `RemindUnansweredTelegram`, `TelegramDailyDigest`, `TelegramWebhook`.
- `WebhookController` — один секрет, один маршрут `/api/telegram/webhook`.
- `telegram_contacts.telegram_user_id` — `unique`: человек, который есть в
  обоих ботах, сломает запись.
- `telegram_contacts.lesson` — NOT NULL, специфично для бота урока.
- `telegram_texts` — ключ текста без бота.
- `FunnelBot::DUE_STEPS` + `telegram:send-reminders` — шаги одного сценария.

### 3.1. Что сделать

1. **Конфиг ботов.** Список ботов с ключом (`lesson`, `diag`): токен, секрет
   вебхука, username, профиль (описание). Админ-группа — **одна общая** ✅
   (`admin_chat_id` остаётся общим). Env-переменные бота урока не менять —
   на проде они уже заданы.
2. **`telegram_contacts.bot`** (string, default `lesson`), уникальность —
   `(bot, telegram_user_id)` вместо `telegram_user_id`. `lesson` — nullable.
   Все выборки контакта по `telegram_user_id` — с учётом бота. Миграция с
   веткой для SQLite (см. CLAUDE.md про тесты).
3. **`TelegramApi::forBot($key)`**; `funnel()` оставить как алиас на `lesson`,
   чтобы не трогать лишнее.
4. **Вебхук** `/api/telegram/webhook/{bot}` — секрет и сценарий по ключу.
   Старый адрес `/api/telegram/webhook` оставить как `lesson`, пока вебхук
   не перерегистрирован. `telegram:webhook {bot}` — регистрирует нужного.
5. **Сценарий** — интерфейс (например `BotScenario`): старт, нажатия кнопок,
   отложенные шаги, свои тексты. `FunnelBot` становится сценарием `lesson`.
   Общее выносится и переиспользуется: запись контакта и сообщений,
   `sendAuto`/`sendHuman` (подпись, «печатает…», окно 10–21), остановка
   автоматики после сообщения человека/ответа админа
   (`automationAllowed()`), `AdminTopics`, `ReminderSchedule`.
6. **Отложенные шаги.** Поля `*_due_at` на контакте общие
   (`reminder_due_at`, `nudge_due_at`, `question_due_at`, `followup_due_at`
   по названию подходят и диагностике); `telegram:send-reminders` берёт карту
   «поле → шаг» у сценария бота контакта. Если семантика полей мешает —
   свои поля, но не дублировать механизм.
7. **`telegram_texts`** — колонка `bot`, уникальность `(bot, key)`; страница
   `/admin/telegram/texts` — переключатель бота. Дефолты текстов диагностики —
   в своём конфиге по образцу `config/telegram_funnel.php`.

### 3.2. Общая админ-группа: ловушки

Оба бота — админы одной группы с темами и **оба получают каждое сообщение**
в группе.

- Ответ админа в теме человека пересылает **только бот этого контакта**:
  контакт ищется по `(topic_id, bot)`; чужую тему бот молча пропускает.
  Человек запускал только своего бота — другой бот написать ему не может.
- Команды в группе (`/chatid`, `/emoji`) отвечает **один** бот (`lesson`),
  иначе ответа будет два.
- Тема создаётся ботом контакта. В название темы — маркер бота (например
  🧪 для диагностики), чтобы админ видел, откуда человек.
- Служебные темы (`telegram_service_topics`) — свои ключи для диагностики
  (например «🧪 Диагностики» вместо общего «📥 Старты»); итог дня
  (`telegram:digest`) — один на группу, с разбивкой по ботам.
- Если человек есть в обоих ботах — это два контакта и две темы. Сводку
  второй темы стоит начинать со ссылки на первую (💡).

### 3.3. Тесты этапа 0

Регрессия бота урока: разбор `/start`, оценка, напоминания, пересылка ответа
админа. Новые: маршрутизация вебхука по ботам, «чужая тема — пропустить»,
один и тот же `telegram_user_id` в двух ботах.

## 4. Mini App ✅ (рекомендация принята к проработке)

Mini App — обычная веб-страница, которую Telegram открывает поверх чата.
Пишем на том же стеке, что вся платформа: Blade + vanilla JS + Tailwind,
страница живёт на p-ege.ru. К странице подключается `telegram-web-app.js`.

### 4.1. Вход

- Бот присылает inline-кнопку `web_app` → `https://p-ege.ru/diag`. 💡 Та же
  ссылка — на кнопку меню бота.
- Страница при загрузке отправляет `Telegram.WebApp.initData` на сервер.
  Сервер проверяет подпись **токеном бота `diag`** (HMAC-SHA256, ключ —
  `HMAC_SHA256("WebAppData", bot_token)`), проверяет `auth_date` (не старше
  суток), находит контакт `(diag, user.id)`. Нет контакта (открыли не через
  `/start`) — создать без метки источника.
- Запасной вход без Telegram: `/diag/go/{link_token}` → cookie, как
  `LessonLinkController`. Нужен для отладки и будущего трафика с сайта.
- Cookie и `localStorage` внутри Telegram не надёжны — состояние только на
  сервере.

### 4.2. Возможности Telegram, которые используем

| API | Где |
|---|---|
| `HapticFeedback` | верный/неверный ответ, свайп, серия, раскрытие балла |
| `MainButton` | «Ответить», «Дальше» |
| `themeParams` / CSS-переменные темы | цвета, светлая/тёмная тема |
| `expand()` / полноэкранный режим | тест на весь экран |
| `close()` | после ответа на «Хочешь улучшить?» — вернуть в чат |
| `shareToStory` | v1.1, карточка результата |

Назад по вопросам не ходим (`BackButton` скрыт): ответ отправлен — он принят.

### 4.3. Сервер — источник правды

Клиент отправляет ответ → сервер проверяет, пишет в лог, двигает автомат,
возвращает пояснение и следующий вопрос. Правильные ответы клиенту до ответа
не отдаются. Закрыл и открыл снова — продолжает с того же вопроса.

Разработка: Mini App требует HTTPS — для локальной отладки туннель
(cloudflared или аналог) или запасной вход по ссылке в обычном браузере.

## 5. Тест: структура и алгоритм

### 5.1. Блоки ✅

1. Человек и общество 2. Экономика 3. Социальные отношения 4. Политика 5. Право

**Порядок — случайный на каждое прохождение** ✅ (временно, пока не
определена сложность блоков). Порядок пишется в лог прохождения.

Прогресс-бар — по блокам («Блок 2 из 5»), не по вопросам.

### 5.2. Адаптивный алгоритм внутри блока ✅

Уровни: Л (1), С (2), Сл (3).

- Блок начинается с Л.
- Верно → следующий вопрос на уровень выше (выше Сл — снова Сл).
- Неверно, и предыдущий ответ в блоке был верным (или это первый вопрос) →
  ещё вопрос **того же** уровня.
- Неверно второй раз подряд → блок закрыт.
- Максимум 4 вопроса в блоке.
- **Итог блока = наивысший уровень, на котором дан верный ответ** (0 — если
  верных нет).

Все возможные пути (сгенерированы перебором, других нет):

| Путь | Итог | Вопросов |
|---|---|---|
| Л✓ С✓ Сл✓ Сл✓ | 3 | 4 |
| Л✓ С✓ Сл✓ Сл✗ | 3 | 4 |
| Л✓ С✓ Сл✗ Сл✓ | 3 | 4 |
| Л✓ С✓ Сл✗ Сл✗ | 2 | 4 |
| Л✓ С✗ С✓ Сл✓ | 3 | 4 |
| Л✓ С✗ С✓ Сл✗ | 2 | 4 |
| Л✓ С✗ С✗ | 1 | 3 |
| Л✗ Л✓ С✓ Сл✓ | 3 | 4 |
| Л✗ Л✓ С✓ Сл✗ | 2 | 4 |
| Л✗ Л✓ С✗ С✓ | 2 | 4 |
| Л✗ Л✓ С✗ С✗ | 1 | 4 |
| Л✗ Л✗ | 0 | 2 |

Автомат — чистый класс без БД, каждая строка таблицы — тест.

За прохождение на одном уровне блока нужно не больше 2 вопросов, поэтому
минимум банка — 2Л + 2С + 2Сл на блок; цель — по 3 на уровень (разные
вопросы при повторном прохождении). Выбор: случайный из неиспользованных в
этом прохождении, с приоритетом вопросов, которые этот контакт ещё не видел.

Почему без подтверждения на Сл (как было в старом ТЗ): на Сл стоят механики
с почти нулевым шансом угадать, а случайные попадания ловит «Наугад» (5.4).

### 5.3. Закрытие блока и переходы

- Начало блока — экран «Блок 2 из 5 · Экономика».
- Блок закрыт двумя ошибками → не «провал», а мягкий экран: «{Блок} — твоя
  точка роста 🎯 Идём дальше».
- 💡 Серии: «🔥 3 подряд!» репликой маскота. За ошибки ничего не отнимаем.

### 5.4. «Наугад» 💡

На каждом экране вопроса — чип-переключатель «🎲 Наугад», нажимается до
ответа. По умолчанию выключен: ноль лишних тапов. Ответ с «Наугад» засчитывается
как обычно (влияет на путь), но отдельно учитывается в результате (7.3, 7.5).

Гипотеза: если по логам «Наугад» почти не нажимают — менять подачу (например,
на две кнопки отправки «Точно» / «Наугад» у механик с кнопкой «Ответить»).

### 5.5. Пояснения ✅

После **каждого** ответа — реплика маскота: верно — 1 строка, неверно — 2–3
строки (в чём ошибка + запоминалка). Тон — забавный, с мемами; мемы — свои
картинки или текст, без фото реальных людей и кадров из фильмов. Кнопка
«Дальше» (MainButton).

### 5.6. Знакомство и цель 💡

Анкеты в начале нет. Маскот первым сообщением: «Привет! Ты в каком классе?» —
варианты **9 класс / 10 класс / 11 класс / Уже закончил школу** ✅ (внизу экрана, как варианты ответа). Один тап, ощущается как разговор.
Пишем и показываем админу; на сам тест класс пока не влияет.

После последнего блока, **перед** раскрытием результата: «На сколько хочешь
сдать?» — ползунок 40–100 (шаг 5) + «Пока не знаю». Создаёт ожидание и делает
результат персональным.

### 5.7. Длительность

Цель 7–10 минут, максимум 20 вопросов. На вопрос: ответ (1–2 тапа) + «Дальше».

## 6. Механики и персонажи ✅ (переработано 24.10.2026)

Основа подачи — **«Кто прав?»** (автору нравится больше всего): ошибка звучит
из уст персонажа, а не как сухое «неверное суждение». Постоянные персонажи
кочуют из вопроса в вопрос (`config/diagnostic.php`, `characters`).

Персонажи морские, как маскот платформы ✅. Каждый — своя типичная ошибка
ученика, поэтому в «Кто прав?» спорят разные способы думать:

| | Характер | Атрибут | Как говорит | Как ошибается |
|---|---|---|---|---|
| **🐡 Рыба-фугу Пыша** (`puffer`) | добрая и наивная | 📱 телефон | мягко, «Ой, а может…», «В тиктоке говорили…» | путает похожие понятия, бытовая логика («штраф — значит уголовное») |
| **🦑 Кальмар Кеша** (`squid`) | хулиганистый, самоуверенный | 🧢 кепка козырьком назад (очки на лбу, скейт/жвачка — по желанию) | коротко, дерзко, со сленгом, «Да я сто раз так делал» | обобщения «всегда/никогда», слишком широкие выводы |
| **🐢 Черепаха Душнила** (`turtle`) | зануда-отличница, дотошная | 📕 круглые очки и толстая книга «Конституция» (закладки, панцирь-ранец) | языком учебника, «Строго говоря, согласно статье 19…» | тонко: формально верно, но мимо сути, не то правило к ситуации — для сложного уровня |

**Каждый бывает прав, примерно поровну.** Если права всегда Душнила, «Кто
прав?» превращается в угадайку «выбери отличницу». Пыша права, когда
житейская логика совпадает с правилом; Кеша — когда дерзкое утверждение
оказывается правдой (момент удивления); Душнила ошибается на сложных.
В пояснениях персонажи в характере: Пыша — «Ой, точно! Я перепутала 🙈»,
Кеша — «Ладно, тут ты меня сделал», Душнила — «Совершенно верно, и обрати
внимание…».

Арт — PNG с прозрачным фоном, квадрат ~512×512, персонаж заполняет кадр,
стиль — как у акулы; три эмоции: обычная / радуется / ошиблась (Пыша прячется
за телефоном, Кеша закатил глаза, Душнила задумчиво листает книгу). Пока
арта нет — эмодзи; картинка — поле `avatar`, без кружка.

Ведущая — **акула** ✅: маленькая акула платформы (`public/img/mascot/level-2`),
для диагностики — обрезанные лёгкие копии `public/img/diagnostic/shark-*.webp`
(обычная / радуется / думает / ошибка). Пояснение после ответа может говорить персонаж: в «Кто прав?»
— тот, кто прав; в остальных — `explain_by` из банка; без него — рыба.

| Механика | Оформление (`skin`) | Подача | Уровни | Засчитывается |
|---|---|---|---|---|
| **swipe** | — / `chat` | карточка-утверждение; `chat` — сообщение персонажа в «чате класса», кнопки «Это правда / Это не так» | только Л | однозначно |
| **single** | — / `case` / `odd` / `who` | один из N; мини-кейс; «Найди лишнее»; **«Кто прав?»** — 2–3 персонажа отвечают со своим объяснением | Л, С | однозначно |
| **multi** | — / `debate` / `fragments` | все верные / «N из M»; **«Помоги выиграть спор»** — персонажу нужны N аргументов, ловушки внутри; **«Ты эксперт ЕГЭ»** — ответ персонажа на задание 2-й части, отметить, за что снять баллы | С, Сл | точное совпадение множества |
| **buckets** | — / `cases` | разложить по группам тапом; `cases` — карточки как сообщения людей («Сосед: ты разбил мой телефон») | С | 100% верно |
| **fix** | — | **«Найди и исправь»**: пост персонажа, спорные слова подчёркнуты одинаково; тап → замена из 3 похожих терминов (текущее — «оставить»). Часть мест верна — ошибки надо найти | С, Сл | все места стоят верно |

**Пропуски в тексте (chips) убраны:** по смыслу и грамматике подходило одно
слово — угадывалось легко. `diagnostic:validate` их не пропускает.

Бинарные (swipe) — только на Л. На Сл — multi или fix.

v2: выстраивание порядка, схема с пропуском, интерактивный график,
«персонажи помнят прошлые вопросы» (реплика акулы «Кеша снова уверен в себе»).

В конце теста одной строкой: «Кстати, всё, что ты решал, — это задания ЕГЭ».

### 6.1. Начать заново ✅

- Посреди теста — «↺ Заново» в шапке, с подтверждением; незаконченное
  прохождение закрывается со статусом `abandoned` (в статистике видно, что бросил).
- На итоге — «↺ Пройти заново» всегда, и до ответа на «Хочешь улучшить?».
  Законченное прохождение остаётся в истории.
- Заново — **с самого начала**, со знакомства («Ты в каком классе?»): класс не переносится ✅.

## 7. Результат

### 7.1. Экран итога ✅ (переработан 24.10.2026)

Экран подстраивается под тип результата. Без карточек — блоки разделены
отступами и заголовками. Сверху вниз:

1. **Вывод акулы** первой строкой:
   - сильный (нет блоков с прибавкой) — слова автора: «Ты хорошо знаешь базовую
     теорию! Вот столько ты сможешь набрать, при условии, что умеешь решать
     задания второй части и знаешь критерии»;
   - средний — «Хорошая база! Есть пара точек роста — и ты на {потенциал}+»;
   - слабый (середина диапазона < 50) — «Есть над чем поработать — и это быстро закрывается».
2. **Балл** крупно (~54–62) и **шкала 0–100**: полоса — диапазон, чёрточка —
   цель, кружок — потенциал (если выше). Подпись «До цели N не хватает ~M».
3. **Сильные стороны** — блоки без прибавки, зелёными чипами.
4. **Точки роста** — блоки с «+N баллов» и полоской; последней строкой —
   вторая часть ЕГЭ (её тест не проверяет). У сильного раздел «Что проверить
   дальше» — только вторая часть и критерии.
5. «🎲 N верных ответов наугад» — если были.
6. **Профиль по блокам** (радар) — свёрнут.
7. **Вопрос под результат**: «Хочешь подтянуть экономику и право?»
   (блоки — в винительном, `config diagnostic.blocks.*.accusative`) —
   [Пока нет] [Да, хочу]; у сильного вопроса нет, кнопка — **«Хочу
   разобраться с этим»** ✅. Обе ведут в тот же путь, что «Хочешь улучшить
   свои знания?» (раздел 8).

Формулировки: «потенциал», «можешь выйти на». Никаких гарантий результата.

### 7.2. Модель ✅ (числа — ❓, все в конфиге `config/diagnostic.php`)

Первичные баллы первой части считаем по измерению, второй — оцениваем.

```
освоение[уровень]: 0 → 0.15, 1 → 0.40, 2 → 0.70, 3 → 0.90     ❓ калибровать

часть1   = Σ по блокам  макс_блока × освоение[уровень_блока]
часть2   = макс_части2 × k × среднее_освоение                   ❓ k = 0.8
первичный = часть1 + часть2
тестовый  = шкала_перевода(первичный)                             ❓ официальная шкала
```

`макс_блока` — сколько первичных баллов первой части приходится на блок,
`макс_части2`, шкала перевода — ❓ автор даст позже; пока заглушка
(равномерное деление, линейная шкала) с явной пометкой в конфиге. Сверять со
спецификацией ФИПИ на 2027 год.

### 7.3. Диапазон ✅

- **Нижняя граница:** уровни блоков считаются так, будто ответы с «Наугад»
  неверные (итог блока — наивысший уровень с верным ответом **без** «Наугад»).
- **Верхняя:** по всем верным ответам.
- Минимальная ширина — ±N тестовых баллов (❓ N = 3), потому что вторая часть
  оценочная. Округление до целых.

### 7.4. Пробелы и потенциал ✅

- «Подтянуть блок» = поставить ему уровень 3, остальное без изменений;
  `+баллы блока` = тестовый(с подтянутым блоком) − тестовый(сейчас), по
  середине диапазона. Считаем в тестовых, потому что шкала нелинейная.
- Потенциал = тестовый балл с двумя слабейшими блоками на уровне 3 (часть 2
  пересчитывается через новое среднее освоение).

Чистый класс без БД, покрыт тестами.

### 7.5. Подача результата

Блоки с уровнем ≤ 1 называем «точками роста», не «провалами». Минимум на
шкале — 15% (уровень 0), чтобы не было «ноль».

## 8. Бот диагностики: сценарий (этап 2) ✅

Все тексты — в админке (`/admin/telegram/texts`, бот `diag`), дефолты — в
конфиге. «Человеческие» сообщения — с подписью Александра, «печатает…», в
окне 10:00–21:00 (ночью — на утро), как в боте урока. Правило из бота урока
сохраняется: **человек написал сам или админ ответил — автоматика замолкает**.

| Шаг | Когда | Что | Тип |
|---|---|---|---|
| Приветствие | `/start <метка>` | Короткое приглашение + кнопка `web_app` «Пройти диагностику» | авто |
| Не открыл | 22–26 ч после старта, тест не открыт | «Получилось пройти диагностику?» + кнопка | человек |
| Бросил | N ч (❓ 3) после последнего ответа, тест не закончен | «Ты остановился на блоке 3 из 5 — продолжим?» + кнопка. Один раз | авто |
| Закончил | сразу | Краткая сводка результата + вопрос «Хочешь улучшить свои знания?» [Да, хочу] [Пока нет]. Если человек уже ответил на странице — сводка без кнопок | авто |
| «Да, хочу» | сразу | «Отлично! Сейчас подключу Александра 🙂» | авто |
| | через 1–4 мин | ✅ «Привет! Посмотрел твою диагностику 🙂 Скажи, а какая тема в обществознании сейчас даётся сложнее всего?» | человек |
| | молчит 24 ч | Одно второе касание (❓ текст) | человек |
| «Пока нет» | сразу | 💡 «Окей! Результат сохранился. Захочешь — пиши сюда, ответит лично Александр» | авто |
| | через 2 дня | 💡 Одно мягкое касание (❓ текст), без предложения занятия | человек |
| Не ответил на вопрос | 24 ч после результата | 💡 Тот же вопрос от Александра, что после «Да» | человек |

Ответ на вопрос (на странице или кнопкой в боте) — один на прохождение;
второй источник после первого ничего не делает. Кнопки в сообщении бота после
ответа заменяются отметкой «✅ Ответ: …» (как `markRated` в боте урока).

**Занятие бот не предлагает** ✅: предлагает админ в живом диалоге, когда
человек сам сказал, что даётся сложно; ссылку на занятие админ шлёт вручную.

Повторное прохождение — 💡 разрешено (кнопка на экране результата), новый
attempt; сводка и аналитика — по последнему законченному.

### 8.1. Админ-группа ✅ (та же, что у бота урока)

- Закончил тест → строка без звука в служебной теме «🧪 Диагностики»
  (имя, класс, балл, источник).
- «Да, хочу» или написал сам → **тема человека** (со звуком — горячий лид).
  Первым сообщением в теме — **сводка**: класс, цель, диапазон и потенциал,
  уровни по блокам, ответы «Наугад», метка источника, ссылка на прохождение
  в админке. Админ начинает разговор с конкретики, ничего не переспрашивая.
- Статус-эмодзи темы — по шагу (закончил / хочет / пишет / молчит).
- v1.1 💡: отметка «записан на занятие» (команда в теме или кнопка на
  странице контакта) — без неё воронку нельзя досчитать до конца.

### 8.2. Аналитика `/admin/telegram`

Фильтр по боту. Воронка диагностики: старт → открыл тест → ответил на класс →
закончил → «Да» / «Пока нет» / без ответа → написал сам → (v1.1) записан.
Разрез по метке источника и классу. Средний балл, распределение уровней по

## 10. Банк вопросов

Автор напишет контент позже ✅. Сейчас — **банк-заглушка**: 5 блоков × 3 уровня
× 3 вопроса, все механики и оформления. Блок «Право» — черновик из старого ТЗ,
переписан репликами персонажей и проверен по фактам; остальные — «[заглушка] …».

Хранение — `docs/diagnostic/questions.json`, проверка — `php artisan
diagnostic:validate` (уникальные id, ключи ответов существуют, хватает
вопросов на каждом уровне, механики по уровням, оформления, персонажи есть в
конфиге). У вопроса — стабильный `id`; в лог пишется `id` + хеш содержимого.

Общие поля:

```json
{
  "id": "law-2-2",
  "block": "law",
  "level": 2,
  "mechanic": "single",
  "skin": "who",
  "prompt": "Пете 15… Кто прав?",
  "explain_correct": "…",
  "explain_wrong": "…",
  "explain_by": null,
  "meme": null
}
```

По механикам:
- `swipe` — `answer: bool`; `chat` — `from` (персонаж);
- `single` — `options[{id,text}]`, `correct`; `case` — `character` (имя);
  `who` — `speakers[{id, who, text}]` (`who` — ключ персонажа), `correct` — id реплики;
- `multi` — `options[]`, `correct[]`, `pick: N` (необязательно); `debate` и
  `fragments` — `from`, у `fragments` ещё `task` (задание 2-й части);
- `buckets` — `buckets[{id,title}]`, `cards[{id,text,from?}]`, `mapping{card→bucket}`;
- `fix` — `text` с местами `{{id}}`, `spots[{id, shown, correct, options[]}]`:
  `shown` — как написано в посте, `correct` — как должно быть; хотя бы одно
  место с ошибкой и хотя бы одно верное;
- `meme` — путь к картинке от корня сайта или https-адрес (появится в пузыре пояснения).

## 11. Данные и логирование ✅

С первого дня пишем всё — через 200–300 прохождений это калибровка
сложности и материал для контента.

- **`diagnostic_attempts`** — прохождение: контакт, статус (начато / закончено),

  на ответ (мс), время на пояснении.

Прохождение видно в админке: в отчёте контакта и по ссылке из сводки в теме.
